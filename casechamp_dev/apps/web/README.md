# CaseChamp web 2.0.0

Клиент D1 для демонстрации «Первый заказ из сообщества». Владелец публикует товарное предложение, покупатель подтверждает тестовый заказ, оператор принимает и исполняет его. Опциональный шаблон B001 ведёт в ту же цепочку через серверный подбор.

## Локальный запуск

Используйте Node.js из [.node-version](.node-version) и npm 10.9.4. Из каталога `casechamp_dev` соберите клиент.

```sh
npm --prefix apps/web ci
npm --prefix apps/web run build
```

Создайте локальное окружение один раз и запустите API, PostgreSQL, worker и Caddy. Если стек v2 уже работает, Caddy увидит обновлённый `apps/web/dist`.

```sh
mkdir -p var
python3 scripts/setup_demo_env.py --output var/compose-v2.env --port 18081
docker compose --env-file var/compose-v2.env -p casechamp-d2-v2 -f compose.yaml -f compose.v2.yaml up --build -d --wait
```

Откройте [демонстрацию](http://localhost:18081/). Caddy обслуживает HTML и `/api/v2` с одного origin. Статус стека доступен через [health](http://localhost:18081/api/v2/health). Подробности эксплуатации приведены в [документации D2](../../docs/backend-v2.md).

Для разработки с Vite используйте `npm run dev -- --host localhost --port 5173` из `apps/web`. По умолчанию прокси направляет запросы в `http://localhost:18081`. Для мутаций настройте `CASECHAMP_WEB_ORIGIN=http://localhost:5173` в отдельном локальном стеке и задайте его адрес в `CASECHAMP_API_PROXY`. Origin формирует браузер. Для интеграционной проверки используйте сборку через Caddy.

## Сценарий демонстрации

1. Создайте демонстрацию. На рабочем столе откройте мастер и создайте предложение с фиксированным составом. Добавьте `MUG × 1` и `TEA × 2`, оставьте самовывоз и отметьте курьерскую зону A. Перейдите к предпросмотру и опубликуйте.
2. В настройках демо выпустите одноразовые ссылки для покупателя и оператора. Откройте ссылки в двух отдельных профилях браузера. В профиле покупателя после входа откройте скопированную ссылку опубликованного предложения.
3. В покупательском профиле выберите одну копию и получение курьером. Проверьте товары на 2 190,00 ₽, получение на 300,00 ₽, итог 2 490,00 ₽. Создайте пятиминутный резерв и подтвердите тестовый заказ.
4. В профиле оператора откройте заказ из очереди, примите его и отметьте исполненным. Профиль покупателя получает актуальный статус при открытии, возврате на вкладку или опросе открытой карточки.
5. Для B001 создайте отдельную демонстрацию с флажком «Добавить демонстрацию подбора». Опубликуйте предложение с одним шаблоном B001. В роли покупателя запросите подбор на четырёх гостей со своей скатертью, самовывозом и сроком один день. При бюджете 5 000 ₽ итог 4 400 ₽, при 4 000 ₽ итог 3 800 ₽, при 3 279,99 ₽ комплект не найден.

## Сборка и проверка

Из `casechamp_dev/apps/web`:

```sh
npm ci
npm run typecheck
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

`CASECHAMP_TEST_ORIGIN` меняет origin тестов. Используйте отдельный локальный стек v2 с таким же `CASECHAMP_WEB_ORIGIN`. Playwright создаёт синтетическую песочницу на сценарий и разные контексты для ролей. HTML-отчёт доступен через `npx playwright show-report`, JUnit записывается в `test-results/junit.xml`. Переменные `CASECHAMP_EVIDENCE_DIR`, `CASECHAMP_RENDER_REPORT` и `CASECHAMP_CHECKOUT_REPORT` задают путь снимков, замеров отрисовки и цепочки заказа. Для записи видео установите FFmpeg с libx264 и выполните `npm run demo:record`. В этом сценарии приглашения создаются и обмениваются в отдельных контекстах вне записи. Путь видео задаёт `CASECHAMP_DEMO_VIDEO`.

Типы, описание операций и схема валидации ответов генерируются из [контрактов v2](../../packages/contracts_v2/openapi.json) при старте, проверке и сборке. Сессия и исходные намерения привязаны к песочнице, поколению и участнику. Повтор команды использует прежний метод, URL, тело и ключ. Результат replay сверяется через чтение ресурса.
