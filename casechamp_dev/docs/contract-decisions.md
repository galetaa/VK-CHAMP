# Решения D2 по контракту 1.0.0

Wire-схемы в `packages/contracts` скопированы из выпуска 1.0.0. Оригинальный архив хранится отдельно. Изменения реализации и принятые трактовки применены в пределах существующего OpenAPI.

| Вопрос | Решение в реализации |
| --- | --- |
| Целевая PostgreSQL DDL | Два выражения `CASE` в проверках номера версии заключены в скобки в первой миграции. Alembic фиксирует свою версию в `public`. Миграции добавляют служебное состояние worker, лимитов, симуляций и сохранение исходного CSV preview. |
| `NO_PURCHASE_REQUIRED` | HTTP 200 с `quote=null` и `minimum_total_minor=0`. Нулевые суммы следуют из исхода. Для отображения количеств D1 использует отправленную форму. |
| Hash импорта | Запрос commit адресует `import_id` и содержит `expected_catalog_version`. Сервер сверяет хеш сохранённых байтов CSV и хеш нормализованных строк preview. |
| Ошибки CSV | Preview сохраняется и возвращает ошибки строк. Commit preview с ошибками возвращает `IMPORT_VALIDATION_FAILED`, превышение лимита — `CATALOG_LIMIT_EXCEEDED`. Уже применённый preview с новым ключом возвращает `IMPORT_NOT_VALID`. Повтор с исходным ключом возвращает receipt. |
| `withdrawSku` и `MutationResult.resource_id` | SKU имеет ASCII-идентификатор, тогда как `MutationResult.resource_id` по схеме является UUID. Для отзыва SKU возвращается UUID соответствующего события мутации. Предмет отзыва уже адресован в URL. |
| Цены, сроки и версии | Канонические версии и timestamps берутся из PostgreSQL. Физические складские изменения увеличивают версию каталога для проверки preview. Простое удержание упаковок меняет inventory version, доступность commit проверяет повторно. |
| Идемпотентность | Ключ относится к operationId и исходному epoch. Хеширует точный HTTP body после проверки схемы и без `client_run_id`. Короткие запросы ждут mutex до 2 секунд. Транзиентные ошибки разрешают повтор по тому же ключу. |
| Замороженное время | `Clock` внедряется через Python в тестах. Публичная симуляция использует отдельный сценарий и SIM SKU, а часы истечения применяются внутри операции к этим ресурсам. |
| Происхождение REPLAY | Ручной контрольный ответ имеет собственный `model_revision=fixture-authored-1.0.0`; lookup использует точный input hash. UUID текущего asset берётся из авторизованного снимка Job. |
