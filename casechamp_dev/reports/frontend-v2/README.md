# Приёмка клиента D1 · CaseChamp 2.0.0

Браузерная приёмка выполнена на чистой PostgreSQL 17.12 через Caddy и FastAPI `/api/v2`. Сборка создана с Node.js 22.21.1 и npm 10.9.4. Базовый коммит backend `d89aa58`, клиент проверен в рабочей копии. Сценарии используют синтетический seed CORE-001 и его расширение B001. Версии и хеши зафиксированы в [environment.json](environment.json).

Клиент прошёл чистую установку `npm ci`, сборку, 19 проверок Vitest и 9 сценариев Playwright. Приёмка выполнена в Chromium на ширинах 360, 768 и 1440 CSS px. Мобильный checkout проверен с увеличением текста до 200%. Тесты открытия, выбора, подсказок и диалогов проверяют Tab, Enter, Escape и возврат фокуса. [Журнал Playwright](playwright.xml)

## Сценарии

| Критерии | Фактический результат |
| --- | --- |
| UI-01, UI-02, UI-20 | Вход в независимых контекстах. Фрагмент очищен до обмена, повтор ссылки отклонён. Чужой Quote и Order скрыты, ожидающая команда очищена при смене покупателя. Сброс восстанавливается исходным запросом после перезагрузки. |
| UI-03–UI-06 | Проверены дробные количества, пустые поля и копейки. Ревизия второго редактора защищена, обе версии черновика видны. Пустой предпросмотр заблокирован для публикации. Готовая версия опубликована с локальной ссылкой. |
| UI-07, UI-08, UI-15 | Исходная стоимость показана в истории после смены цены. Новое согласие нужно после перепубликации. Нехватка товара блокирует расчёт. Архив отменяет активный резерв, а пауза сохраняет созданный заказ. |
| UI-09, UI-10, UI-12 | Ровно на `expires_at` расчёт закрывается, GET повторяется. Повтор резерва сверяет актуальное состояние и показывает EXPIRED после чтения. Отдельная живая проверка подтверждает отмену. Запоздалый ответ не переоткрывает checkout. |
| UI-11, UI-20 | Потеря ответа после успешного confirm и перезагрузка возвращают один заказ с теми же ключом и телом. [Проверенная цепочка заказа](core-order-chain.json) |
| UI-13, UI-14, UI-18 | Реальная очередь использует ID ASC и курсор. Конкурирующая отмена возвращает остаток один раз. Клиентский просмотр не меняет число заказов, тестовые показатели помечены. |
| UI-16, UI-17 | Покупатель проходит 360 CSS px без горизонтальной прокрутки. При 200% итог читается, резерв и подтверждение остаются доступны. |
| UI-19 | B001 даёт 4 400,00 ₽ и 3 800,00 ₽ при контрольных входах, NO_SOLUTION при 3 279,99 ₽. Отдельный 503 отображается как сбой расчёта. Подобранный комплект проходит через Quote, резерв и заказ. |

Для UI-09/UI-10 Playwright подаёт контрольные часы в HTTP-ответе и конечное состояние в GET после реального идемпотентного replay. Для UI-19 он подаёт контрактный 503. Проверки серверного истечения, транзакций и нагрузочный профиль находятся в [отчёте D2](../V2.md).

Измерение отрисовки использует браузерный `responseEnd` и первый запрошенный кадр с данными. Оно выполнено в одном контексте на CORE-001 с пятью прогревочными переходами на экран. Настройка воспроизводится в [тесте отрисовки](../../apps/web/e2e/render.spec.ts). [Замеры p50 и p95](render-latency.json)
