# VK CaseChamp 2026 — полный анализ в Jupyter и uv

В проект входят оригинальный датасет, условие кейса, выполненный Jupyter-блокнот, HTML-версия,
Python-код всех расчётов, полные CSV/JSON-таблицы и графики. Предыдущий анализ сохранён,
дополнительные проверки вынесены в отдельные разделы. Версия исследования — 19 ноября 2026 года.

**Данные синтетические.** По условию организаторов они не отражают реальные показатели VK.
Период агрегатов — 1–30 сентября 2026 года. Ассоциации в одном срезе не доказывают причинность.

## Быстрый запуск

Распакуйте архив целиком и откройте терминал в папке vk_case_analysis_uv.
Нужен uv; инструкция установки находится на https://docs.astral.sh/uv/getting-started/installation/.

    uv sync --locked
    uv run --locked jupyter lab VK_full_analysis.ipynb

В Jupyter можно просто читать сохранённые результаты или выбрать «Restart Kernel and Run All Cells».
В VS Code выберите интерпретатор из созданной папки .venv.

Чтобы пересчитать все ячейки без сервера:

    uv run --locked python scripts/execute_notebook.py

Эта команда запускает ячейки последовательно в общем пространстве IPython внутри нового процесса
Python из текущего uv-окружения. Выводы, таблицы и изображения получаются фактическим выполнением
кода и записываются обратно в VK_full_analysis.ipynb. Затем обновляется VK_full_analysis.html.
При ошибке выполнение останавливается, а промежуточный блокнот сохраняется в analysis/failed_execution.ipynb.

Для выполнения через стандартное отдельное ядро Jupyter предусмотрен вариант:

    uv run --locked python scripts/execute_notebook.py --engine jupyter

В этом варианте на Linux/macOS используется локальный IPC, на Windows — loopback TCP.
При необходимости транспорт можно явно выбрать аргументом --transport tcp или --transport ipc.

**Фактически проверенный способ:** последовательное выполнение всех ячеек через IPython
в новом процессе uv. Обычный запуск ядра Jupyter и Jupyter Server в среде подготовки заблокирован
ограничением локальных соединений; его успешный запуск здесь не заявляется. Режим выполнения
зафиксирован в metadata/execution.json.

Для чтения без Python и Jupyter откройте VK_full_analysis.html в браузере.
Числовые таблицы и изображения уже включены в HTML; ссылки на полные CSV работают,
если сохранена вся структура папки.

После распаковки окружение .venv создаётся заново командой uv sync --locked; в архив оно не включено.

к внешним сервисам не обращаются.

Перед передачей архив распакован в отдельную папку. Из копии удалены 166 производных файлов
и все сохранённые выводы ячеек, после чего заново созданы окружение и результаты.
Все 38 кодовых ячеек выполнились без ошибок, все 21 контрольная проверка прошла.
Семь файлов аналитических результатов совпали с основным прогоном; единственное отличие
в служебных данных аудита — абсолютный путь к исходному Excel в другой папке.

Флаг --locked запрещает незаметное обновление lock-файла при запуске.
Если вы намеренно меняете зависимости, обновите pyproject.toml и выполните uv lock,
затем повторите проверку результатов.

## Что добавлено к прежнему анализу

### 1. Одновременный учёт размера аудитории и каталога

Для 3 859 активных каталогов без реферальной программы исходное отношение долей бизнесов
с заказом для товарных публикаций составляет 2,428. После совместной стандартизации
по сетке 5 × 5 оно равно 1,436. Это уменьшение описательного различия после выравнивания состава,
не оценка причинного эффекта публикаций.

При требовании минимум пяти наблюдений в каждой ветви остаются 2 533 бизнеса, или 65,64%.
В этой сокращённой совокупности исходное отношение равно 1,954, стандартизированное — 1,401.
В блокноте эти две совокупности показаны раздельно. Сохранены 80 сравнений и 680 строк ячеек.

### 2. Устойчивость кандидатов и рекламных сумм

При обоих порогах подписчиков/просмотров 800, 1000 и 1200 остаётся соответственно
410, 366 и 336 кандидатов при остальных неизменных правилах.
Замена трёх условий ≥ на > оставляет 338 вместо 366.

У 39 из 366 кандидатов есть рекламные траты. Медиана по всем кандидатам — ноль,
среди рекламодателей — 61 тыс. рублей. Один бизнес формирует 72,21% суммы.
Общие рекламные траты не являются типичным или доступным бюджетом пилота.

### 3. Пересечения диагностик и их объёмный вес

Объединение трёх выбранных контентных диагностик затрагивает 67 из 9 754 строк.
У этих строк находится 56,75% обычных репостов, но 1,01% checkout-заказов.
Это доли показателей у затронутых строк, а не доли доказанно ошибочных событий.
После узкого исключения знак описательной связи публикаций и наличия заказа сохраняется.

### 4. Границы при пропусках оценки автора

В активных каталогах без рефералки известные метки дают разницу долей с заказами +2,37 п.п.
Допустимые заполнения пропущенных меток дают диапазон от −4,20 до +8,12 п.п.
Без предположений о механизме пропусков знак связи для всей выбранной совокупности не определён.
Это границы совместимых заполнений, а не доверительные интервалы и не эффект реальной оригинальности.

### 5. Риск автоматической очистки среднего чека

Исключение строк с |исходный средний чек − GMV / заказы| > 1 рубля удаляет 287 из 298
бизнесов с заказами и оставляет только 11. Такая «очистка» отбирает наблюдения по исходу.
Поэтому исходный средний чек сохраняется, а пересчитанное отношение хранится отдельно.

### 6. Сценарная мощность эксперимента

При условной будущей частоте заказа в контроле 3%, равном распределении 366 участников
и заданном изменении до 8% мощность двустороннего точного теста Фишера составляет 47,61%.
Для мощности 80% в этом сценарии требуется частота воздействия около 10,66%.

Исходная частота 3% здесь является допущением, а не оценкой из данных.
Прошлый ноль заказов в сегменте не означает нулевой будущей частоты.
В полном приложении сохранены 108 сценариев мощности и 36 минимально обнаружимых различий.

## Как читать результаты и менять параметры

Сначала прочитайте разделы 1–4, затем интересующий предметный блок.
Новые исследования находятся в разделах 22–26, гипотезы — в разделе 27,
глубокие диагностические приложения — в разделе 28.

Пороги SUBSCRIBERS_MIN, VIEWS_MIN и ACTIVE_PRODUCTS_MIN можно менять в разделе 13
и повторно выполнять эту ячейку. Источник при этом не изменяется.
Расчёт новых сценариев мощности находится в функции pilot_power модуля robustness_analysis.py;
сохраняйте явные допущения и одинаковый размер ветвей для текущей реализации точного теста.

Текущие проверки хеша рассчитаны на оригинальный снимок. Для нового Excel недостаточно
просто заменить файл: нужно проверить порядок и смысл полей, временные окна,
пропуски, контрольные суммы и фиксированные пояснения.

Повторное выполнение переписывает производные JSON/CSV, автоматически генерируемые разборы,
PNG, результаты блокнота и HTML. Собственные заметки сохраняйте в отдельном файле.
Матрица доказательств и docs/robustness_findings.md — аналитический текст для исходного снимка;
все приведённые в нём числовые результаты пересчитываются соответствующими модулями.

## Ограничения, которые сохраняются после пересчёта

- Нет связанных событий покупателя и заказа, поэтому агрегатные отношения не являются
  доказанными пользовательскими конверсиями.
- Есть крупный обход карточки у Партнёра и неизвестный источник «Другое».
- Суммы категориальных заказов не сведены с общими итогами; используются собственные знаменатели.
- Неизвестные значения не заменяются нулями. Ноль внутренних заказов не означает отсутствия всех продаж.
- Размер и способ формирования бизнес-выборки не позволяют переносить доли на всю платформу.
- Диагностические модели используют признаки и исход одного месяца; они не являются прогнозом.
- Стандартизация учитывает только выбранные наблюдаемые размеры и не устанавливает причинный эффект.
- GMV не является выручкой, а общие рекламные траты нельзя полностью приписывать checkout-заказам.

Ссылки на определения и условие находятся в самом блокноте, в подробных разборах
и в docs/evidence_matrix.md. На другом процессоре возможны небольшие различия плавающей точки
и оформления графиков; счётчики, фильтры и знаменатели должны совпадать.
